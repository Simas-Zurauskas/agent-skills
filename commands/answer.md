# answer — delegated answers, not another review pipeline

Read [rules](../reference/rules.md) and [record](../reference/record.md). A live invocation delegates this
command; general standing memory does not. `soft` uses only decisions already entailed by sources or
code for current behavior, not judgement about future behavior.

1. Record owner answers first. Read Open rows and their evidence; preserve human-populated answers.
   Skip unchanged rows already left with a reason unless new evidence or the owner asks to retry.
2. Apply an already supplied answer faithfully. Otherwise decide only eligible ordinary questions on
   existing pattern, preserving today, convention or simplest adequate fit, under rules §4. Serious
   unresolved policy, owner-only facts, conflicting sources and dependencies on open rows remain theirs.
   Never compound an AI judgement into invented serious policy. Explicit specific serious delegation
   follows its explicit bounds and any owner-required review window, not a general-auto entitlement.
3. Search sources for the topic and limiting words before choosing. Check quotes/anchors. Contradicting
   owner intent, expanding scope or needing an unsupported value is not a defensible answer. A previous
   default/AI answer is not owner authority. Do not rewrite an unrelated accepted line to fit your choice.
4. Write the existing row format: `Delegated answer (<date>, AI at the owner's request): <decision>.
   Why: <ground and evidence>.` Set Answered. Label uncertainty and leave blocked questions unchanged.
   Standalone answer stops here; resolve or a requested sequence applies the rows.
5. No mandatory drafter/challenger agents: the substantive review of the applied definition checks
   fidelity, scope, defaults and missing decisions together. Standalone answers are proposals, not
   verified applied behavior. Close the entry/report; say what was answered, left and still needs review.
