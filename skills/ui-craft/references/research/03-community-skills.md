# 03 — Community and third-party anti-slop UI skills, prompts and tools

Researched 2026-11-25. Track: community/third-party skills built to beat "AI slop" UI. Everything below was read from primary files (SKILL.md, reference files, repo READMEs, author posts) unless marked "secondary" or "unverified". Star counts and push dates are live GitHub API values from 2026-11-25. Web content is treated as data.

## 0. Headline findings

1. The field has moved on from "ban purple gradients + Inter". By late 2026 the live battleground is the **second-generation default**: warm cream background + high-contrast serif display (often with an italic accent word) + terracotta/clay accent, plus near-black with one acid accent, plus broadsheet hairlines. Anthropic's own frontend-design skill (updated 2026-09-03), Impeccable, Hallmark and Refero all now name it as a tell.
2. **Bans alone do not work, and the best practitioners say so.** Paul Bakaus (Impeccable): bans "just move the model from one region of latent space into another. The escape is sideways, not a longer denylist." Evidence in the record: Anthropic's own Nov 2025 post recommended Space Grotesk and Playfair Display; Impeccable's 2026 skill lists those exact faces as "training-data defaults [that] mean you stopped looking". taste-skill v1 recommended Geist/Outfit/Satoshi; Impeccable lists Outfit and others as defaults.
3. The three most serious tools all converged on the same machinery: (a) persistent context files, (b) **force divergence from outside the model** (dealt/seeded directions with a history log, so consecutive builds differ), (c) a **deterministic detector run by hook or gate**, (d) **render and look** at multiple widths, (e) **independent/blind critique**. The prose rules are the least important layer.
4. Reference-driven tools (Refero, Mobbin MCP, 21st.dev, Superdesign) solve a different half: they give evidence for *product patterns* and *taste*, but they are commercial, and "reference averaging" (blending references into a safe middle) is a named failure mode.
5. Evidence of real-world effect is thin and mostly self-reported. Best data points: Vercel's own eval of its design.md (57% fewer known failures; n=6 pages, mechanical checks only) and SkillGild's one-brief comparison (skills "change direction more than quality"; costs 1.6x to 7.6x). Star counts are enormous but not trustworthy as a quality signal.
6. Practical warning for this Mac: several tools (Impeccable detect-by-URL and `shot`, taste-skill scripts, Hallmark `sloplint --render`) launch the user's installed Chrome/Edge headless. Our rule is chrome-headless-shell only. taste-skill reads `CHROME_PATH`; check the others before adopting any of them.

## 2. Per-source detail

### 2.1 Impeccable (pbakaus) — the most influential, and genuinely novel

**Current shape (v4.11, 2026-11-24).** One router `SKILL.md` (13.7 KB) + ~45 reference files loaded on demand + an engine binary (Rust, ships with the skill) + CLI (`npx impeccable ...`) + hooks + Chrome extension. It is no longer "a prompt"; Bakaus calls a skill "a harness extension".

**Commands (24).** Steer: `bolder`, `quieter`, `distill`, `colorize`, `typeset`, `layout`, `animate`, `delight`, `overdrive`. Review: `critique` (scored UX review), `audit` (a11y/perf/theming/responsive, P0-P3). Finish: `polish`, `harden`, `clarify`, `adapt`, `optimize`, `onboard`. Iterate: `live` (pick an element in the browser, cycle variants, write back to source), `generate`. Plan/setup: `shape`, `init`, `document`, `extract`. `craft` is a deprecated alias for a normal build. Rationale ("design vocabulary"): "'Make it pop' leaves your agent to guess. `/impeccable bolder the pricing cards` loads a playbook written for that one move."

**Context files (answers the "design-context file" question).** Current: `PRODUCT.md` (audience, goals, platform, constraints, brand commitments, "anti-references"; written by an interview in `init`), `DESIGN.md` (visual system; uses the Google DESIGN.md YAML frontmatter + prose; written *from the built result* by `document`, not before), `.impeccable/design.json` (generated token metadata), `.impeccable/surfaces/*.md` (one brief per route, holding the chosen mode and a "Direction contract"), `.impeccable/config.json`. The older name `.impeccable.md` is the pre-v3/v4 file, superseded by PRODUCT.md/DESIGN.md. Key principle in new-work.md: "a rulebook written before the build gets defended against reality instead of describing it". Missing context warning: "Missing or vague context can lead to more generic design."

**Modes.** Persuade / Operate / Read / Experience, chosen "from the requested surface, not the product" (a tool's landing page is still Persuade; its docs are Read). Operate/Read: "ambition shows as precision and restraint". Persuade/Experience: "full commitment: bold, distinct work with a point of view."

**Craft floor (the checkable part, `reference/craft-floor.md`).** Quotes:
- Contrast >=4.5:1 body, >=3:1 large; "On colored surfaces tint secondary text from that hue or the foreground; never gray."
- "shadows carry an offset and a soft blur. A zero-offset colored halo is decoration."
- "body measure 65-75ch, display max 6rem, tracking floor -0.04em, balanced headings"
- Motion: "one authored moment, not scattered effects and not one identical entrance on every section. Exponential ease-out from an already-visible default."
- "Browser surfaces: the parts you did not draw still carry the design. Text selection, the caret, custom scrollbars, focus rings, underline offset, and the numerals in tabular data ... This is the cheapest signal that a page was built rather than assembled, and the one models skip most reliably."
- Refuse list: same-size icon+heading+text cards ("Cards are the lazy container; nested cards are always wrong"); hero-metric template; "A kicker or eyebrow above a heading. This one is a ban, not a default: no brief earns it back."; section numbers unless a real sequence; gradient text; decorative glass/blur; one-sided colored border bars; hard offset shadows outside a real neobrutalist world; sparklines/progress rings as filler; monospace "as a costume for technical"; a system display face as display voice; Unicode glyphs/emoji as icons; geometric masks faking organic cutouts; "Light or dark picked by category."
- Model-specific blocks (`<codex>`, `<claude>` tags): ghost card (1px border + wide soft shadow), over-round (>16px on cards), sketchy SVG illustrations, `feTurbulence` grain, decorative stripes/grids. For Claude: "Your measured rendition prior: warm, bookish, family, and child-facing subjects come out as cream grounds, serif display with italic accents, and lamplight... Treat that first palette as already spent." (Directly relevant to wedding/family products.)

**Detector.** "62 deterministic rules + 6 design-review patterns", no LLM. Categories include: overused font; single font for everything; flat type hierarchy; icon tile above heading; italic serif display headline; badge above headline; label above heading; oversized hero headline; crushed letter spacing; AI color palette; dark mode with glowing accents; gradient text; gray text on colored background; cream/beige palette; tiny numbered section labels; hero metric layout; identical card grids; nested cards; monotonous spacing; side-tab accent border; hairline border + wide shadow; extreme radius; decorative grid/stripes/halo/spotlight; glassmorphism; pulsing status dot; decorative blinking cursor; auto-scrolling marquee; bounce/elastic easing; em-dash overuse; generic marketing claims; "calling things theater"; placeholder illustrations; plus quality checks (cramped padding, tiny body text, low contrast, tight line height, skipped headings, text overflow, clipped popovers, justified text, JS errors, broken images). Plus design-system drift rules (font/color/radius/size outside DESIGN.md). Delivered three ways: PostToolUse **hook** after each edit (most important), CLI/CI (`detect`, SARIF, exit codes), Chrome extension overlay. Waivers: `impeccable-disable <rule>: reason`, value-level ignores (`add-value overused-font Inter --reason "Brand font"`).

**Anti-slop process (the genuinely novel part).**
1. *Forced divergence from outside the model.* New visual world: write the product's mechanism, audience scene, cultural home; list **seven** concrete visual systems/artifacts/places/rituals the audience knows (must span >=3 material families; "nameable abstract system (a school of poster, a documentation standard) is as concrete a candidate as any artifact"; ask "what would this look like as a physical object and what did its world look like before the web"); then run `impeccable concept-seed`, a script that **rolls** the assigned direction and deals catalog "challengers". "No substitute, no skip: ... the roll is what keeps every run from converging on the category default." The agent must fuse each challenger and judge on two axes (audience identification, product clarity), a declined challenger donates one *discipline* (never "clothes"). One "Impeccable's pick" card and a standing exit "category standard, played straight" so the user can choose familiar. Bakaus' three techniques (article): "shave the safe picks: make the model name its top 3 fonts, then discard all three"; generate ~50 and let a blind sub-agent keep the 5 most distinct; "seed from outside the model: `palette.mjs --from 8f2a`".
2. *Category-reflex check, two altitudes* (v3.9 SKILL, still the idea): "First-order: if someone could guess the theme + palette from the category alone, it's the first training-data reflex... Second-order: if someone could guess the aesthetic family from category-plus-anti-references ('AI workflow tool that's not SaaS-cream -> editorial-typographic') it's the trap one tier deeper."
3. *Colour strategy before colours*: Restrained / Committed (one colour 30-60%) / Full palette / Drenched. "Dark or light is never a default: write one sentence of physical scene (who uses this, where, under what light) and let it force the answer."
4. *Fonts*: list of "training-data defaults [that] mean you stopped looking": Fraunces, Playfair Display, Cormorant, Lora, Crimson, Newsreader, Syne, Space Grotesk, Space Mono, IBM Plex, Inter-as-display, DM Sans, DM Serif, Outfit, Plus Jakarta Sans, Instrument Sans. "a subject association is never that reason: books wanting a serif, bookshops wanting hand-lettering, and tech wanting a mono are the associations the list exists to break."
5. *Calibration of what AI converges on* (SKILL/new-work): "warm cream ground, high-contrast serif display, and a terracotta or signal-red accent; near-black with one neon accent and glowing edges; broadsheet-editorial hairlines, italic display serif, and small tracked mono labels; flat saturated ink with black boxes, hard offset shadows, and heavy condensed display type. All are legitimate when the brief calls for them."
6. *Brief wins*: "Honor pinned aesthetics, eras, materials, fonts, and palettes even when they conflict with a saturated-pattern warning. Redirecting a clear brief toward your taste is failure."
7. *Direction contract* recorded before code (six blocks, ~150 words): THESIS (and the default arrangement it refuses), OWN-WORLD (palette+components "specific enough to be recognizable with all content removed"), STORY, FIRST VIEWPORT, FORM, seed reference. Never copied into shipped code.
8. *Critique*: two **isolated** sub-agents. A = LLM design director (first judgement: "Design specificity: Is the composition, interaction, and visual language grounded in this product, or could an unrelated product use it unchanged?", Nielsen heuristics 0-4, cognitive load, personas incl. project-specific ones from PRODUCT.md Users). B = detector + browser evidence. They must not see each other's output ("hand the LLM the detector output up front and it skews BOTH ways"). Snapshot persisted; `polish` reads the latest critique as its backlog; score trend tracked (24, 28, 32).
9. *Truth binds claims*: author illustrative material at full fidelity, label synthetic, never invent "prices, customers, benchmarks, endpoints, capabilities". SkillGild: Impeccable was the only run that did not invent product facts.
10. Visual verification: `impeccable shot <page>` batched at shipped sizes; "fix what one look shows before looking again".

**What is genuinely new:** (a) divergence by dice/seed + history + challenger fusion; (b) hooks that fire without invocation; (c) blind two-agent critique; (d) per-model defect blocks (Gemini hover-scale images, GPT -0.06em tracking, Claude italic serif/eyebrow/pulsing green dots); (e) detector keyed to DESIGN.md so *drift from your own system* is flagged; (f) modes that scale ambition.
**Weaknesses:** 7.6x cost and 46 turns in SkillGild's one-brief run; very long procedure (decision pages, comps, daemon servers) a lesser model may skip (Bakaus: "Design for the weakest model: gates that can't be skipped"); hooks run outside model approval (README warns); catalog fetch + anonymous telemetry; browser launch uses installed Chrome/Edge. Also strongest on existing interfaces ("Impeccable is strongest on interfaces that already exist"); new-page generation is "harder mode". No independent proof that dice-assigned directions are better than the model's own.

### 2.2 taste-skill (Leonxlnx)

Two incompatible eras:
- **v1 (Feb-Oct 2026, now `taste-skill-classics`)**: three numeric dials (DESIGN_VARIANCE 8, MOTION_INTENSITY 6, VISUAL_DENSITY 4); "Bias Correction" directives; section "7. AI TELLS (Forbidden Patterns)": no neon glows, no pure #000, no oversaturated accents, no gradient text, no custom cursors; "NO Inter Font: Banned. Use Geist, Outfit, Cabinet Grotesk, or Satoshi"; serif banned on dashboards; "THE LILA BAN"; "ANTI-CENTER BIAS: Centered Hero/H1 sections are strictly BANNED when DESIGN_VARIANCE > 4"; "NO 3-Column Card Layouts"; "Jane Doe effect" (no John Doe/Acme/Nexus, no 99.99%, no round numbers); mandatory loading/empty/error states; `min-h-[100dvh]` not `h-screen`; Tailwind/Phosphor/Radix specifics. Textbook ban-list skill: easy to follow, and visibly produced its own cliché (Geist/Satoshi/Zinc/bento/magnetic buttons/"liquid glass").
- **v2.5.1 (current)**: rebuilt as "professional company websites at the figma.com and x.ai level". A template kit (`starter.html`, `system.css`, 11 dealt hero layouts, 16 CSS grounds, UI fragments, shader/scene "moments" **only on tech/gaming/software**) plus scripts: `start.mjs deal` (palette by trade + Google Fonts pairing, with a history file), `layout/deal.mjs`, `moments.mjs`, `photos.mjs` (vetted real photographs, credited), `icons.mjs` (real brand icons), `copy-lint.mjs`, `consistency.mjs` (>100 browser checks at 1440/1024/820/768/390), `gate.mjs` (Stop hook; blocks finish until no fixable FAIL; 3 rounds). House rules include: one section per screen, equal left/right edges, no captions under images, every visual must render, "60 to 80 words a screen", copy fact sheet and voice card, "Deal, never choose by taste."
- Best part: `references/copy-tells.md` (dated Nov 2026): "the tells move with every model generation, so learn why each one reads as a model and do not just memorise the list... every rule that bans a habit needs a positive move beside it, or the model reaches for the nearest substitute." Second-generation copy tells include: "the house voice (warm, wry, modest, a little literary, for every client)", invented specifics ("6:12 a.m., from the window of Room 9", "Batch No. 047"), "strip of figures", two-fragment headings "X. Y.", -ing riders, "serves as", question-then-answer reveal ("The result? ..."), em dashes, dead metaphors (journey, ecosystem, landscape).
- Weaknesses: v2.5 pushes every output into one template kit with a finite hero set (convergence *across users*, even if consecutive builds differ); mandates motion on every page (hero entrance + dealt moments + hover lifts) whereas Anthropic/Hallmark/Vercel say stillness by default; scoped to company marketing sites, not app UI; its 40-item checks missed two of its own checks in SkillGild's test; independent blind test headline is negative on cost-benefit (secondary). Scripts drive headless Chrome themselves (set `CHROME_PATH`).

### 2.3 UI Skills (ibelick)

- `baseline-ui` (the "deslop" skill): RFC-2119-style MUST/NEVER list. Quotes: "NEVER add animation unless it is explicitly requested"; "MUST animate only compositor props (transform, opacity)"; "NEVER exceed 200ms for interaction feedback"; "MUST use text-balance for headings and text-pretty for body"; "MUST use tabular-nums for data"; "NEVER modify letter-spacing unless explicitly requested"; "NEVER use gradients unless explicitly requested"; "NEVER use purple or multicolor gradients"; "NEVER use glow effects as primary affordances"; "SHOULD limit accent color usage to one per view"; "MUST give empty states one clear next action"; "MUST use an AlertDialog for destructive or irreversible actions"; "NEVER use h-screen, use h-dvh"; Tailwind defaults, Base UI/Radix/React Aria primitives, `aria-label` on icon buttons. Pure hygiene; it makes everything *competent and bland* (gradients and animation off by default), not original.
- `improve-ui`: read-only audit with a **three-proof gate** per finding: Contract (a binding design decision or direct contradiction), Runtime (the owner actually reaches the surface), Correction (one change, no invented intent). Max three findings; writes plans for another agent. Excellent anti-hallucination discipline: "prefer no finding to an unsupported one."
- `create-design-md`: builds DESIGN.md from a repo or a URL (rendered computed styles), with an evidence ledger (role -> value -> source -> scope -> recurrence -> confidence), validates with `npx @google/design.md lint` + `export`, and "do not promote accidental implementation patterns into design decisions."
- Registry: `npx ui-skills list/get`, MCP `list_skills/get_skill`, "Playbook" lessons. Credible and clean; low-risk to borrow wording; not a source of originality.

### 2.4 Hallmark (Nutlope / Together AI) — the best compact rule architecture

- **Tiered gates**: *Floor* (never ships, no waiver): tokens at `:root` only, no `transition: all`, never one italic word in a roman heading, `overflow-x: clip`, `minmax(0,1fr)` image tracks, `:focus-visible` everywhere, reduced-motion fallbacks, "Never an invented metric, testimonial, logo wall or case-study count", "Never an eyebrow, and never a label in tracked capitals or small caps", no middle-dot meta strings / arrows glued to links / decorative status dots, no purple-to-blue gradient, no card in a card, no emoji icons, no hand-drawn browser windows, hero headline+sentence+action visible at 1280x800, "About 80 words on any one screen", container capped at 1920. *Reflex* (model defaults; waivable on the record with a reason): Inter/Roboto/Poppins as display, zero-chroma neutrals, accent past ~5% of viewport without declared posture, glow/aurora blobs, the named look "cream paper (L>=90, hue 55-105), high-contrast serif display and a terracotta/clay accent (hue 15-55)", framework default swatch (Tailwind indigo-500), "mono as costume", identical section gaps, "The AI template (hero, three features, call to action, footer), or the same shape as one of the last three logged builds". *Finish* (craft detail, never blocking). ~85 numbered gates, each class-tagged M (mechanical) / R (render) / J (judged).
- **Dealt direction + build log**: `theme.mjs deal` offers three of **fifty "materials"** (a theme = paper, type, colour, surfaces, components, texture; "never says what a page contains or in what order") that fit the prompt and clear `.hallmark/log.json`; `theme.mjs draw` deals the page anatomy from the visitor's **job** (book / buy / subscribe / visit / hire). "Mirror test: would a neighbouring prompt in the same category get this exact combination? If yes, change one decision and say which." Page must also differ from the last three logged builds on 3 of 6 structural axes.
- **Material first**: "ask once: Material (screenshots/photos/real numbers), Audience, Use, Tone"; "Facts are never inferred"; stand-in photos from a 755-photo licensed library, credited.
- **Build order**: hero built **alone**, linted, reviewed cold in fresh context before the rest exists. Then `sloplint --render` at eight widths, then a fresh-eyes sub-agent.
- **Pre-emit critique**: six axes scored 3-5: Philosophy ("has an argument a reader could disagree with"), Hierarchy ("survives the squint test"), Execution, Specificity ("could belong to no other product"), Restraint ("lost something you liked"), Variety.
- Signature: "the one thing a visitor would remember: the prompt's strongest real thing shown at its best" (a number drawn as marks is a device, not a signature).
- Weaknesses: opinionated house rules presented as law (no uppercase labels at all, no em dashes, 80 words/screen) that will not suit every product; 50-theme catalog is itself a finite palette of looks; marketing-site oriented (app screens get a short path); Node + browser dependency.

### 2.5 UI UX Pro Max (nextlevelbuilder)

Python search over CSVs of styles/palettes/fonts/UX rules + a "reasoning engine" that outputs `PATTERN / STYLE / COLORS / TYPOGRAPHY / KEY EFFECTS / AVOID` per product category. Example in README: spa -> "Soft UI Evolution", Cormorant Garamond/Montserrat, soft pink + gold, "AVOID: bright neon + dark mode + AI purple/pink gradients". It gives professional-looking, *predictable* output (the first-order reflex Impeccable warns against: "if someone could guess the theme + palette from the category alone ... "). Useful as a **UX-rule lookup** (119 guidelines), not as an originality engine. Largest star count of any design skill; SkillGild ranked its output the most conventional.

### 2.6 Anthropic frontend-design (current, 2026-09-03) — the baseline everyone fights or forks

Short (71 lines) and, notably, the most self-aware list. Key lines:
- "Approach this as the design lead at a design studio known for giving every client a distinct visual identity that is not mistaken for anyone else's."
- "Ground your designs in the subject matter... The subject's industry, subject matter, materials, and vernacular are where distinctive visual choices come from."
- "Open with the most characteristic thing in the subject's world... a big number with a small label, supporting stats, and a gradient accent is the default treatment."
- Typography: "Choose your typefaces deliberately, not the default families you would reach for on any other project." Avoid: "Accenting just a single word or phrase in a headline"; "all caps for labels"; "unnecessary typographic labels above content". "Visual structure is information... numbered markers (01 / 02 / 03) ... only appropriate if the content actually is a sequence."
- Motion: "A single orchestrated moment... fade-and-slide-up entrances on each section and hover transitions on every card are the generic default."
- **Calibration list** (5 clusters): cream (#F4F1EA) + serif + terracotta (#D97757, "Anthropic's own Claude-interaction accent, so on a user's brief it reads as a tell"); near-black + acid green/vermilion; broadsheet hairlines/zero radius/dense columns; the SaaS-card kit (identical rounded cards, one radius everywhere, same grey shadow, gradient washes); template chrome (tracked ALL-CAPS eyebrow, middle-dot meta strings `A · B · C`, `WORD — fragment` labels with spaced em dash, tinted near-black #0B0B0B/#111 standing in for black, mono for small data labels, `→` appended to links). "All traits are legitimate for some briefs, but they are defaults rather than choices."
- **Process**: "Work in two passes": brainstorm a compact token plan (4-6 named hex colours; type roles; layout concept in prose + ASCII wireframes; principles) then "review that plan against the brief before building: if any part ... reads like the generic default you would produce for any similar page (work through a similar prompt to see if you arrive somewhere similar) ... revise that part, say what you changed and why."
- "Spend your boldness in one place. Let one element be the memorable thing... Chanel: before leaving the house, take a look in the mirror and remove one accessory." Quality floor unannounced; "taking screenshots to review".
- UX writing section (active voice, "Save changes" not "Submit", same action keeps the same name, errors don't apologize).
- Original Nov 2025 post: "distributional convergence ... Claude samples from this high-probability center." It recommended specific fonts (Space Grotesk, Playfair Display, Crimson Pro, JetBrains Mono ...) which later became tells: proof of the ban/recommend-list decay.

### 2.7 Vercel design.md / product-design (best methodology evidence)

- `design.md` (public file, ~40 KB at vercel.com/design.md) + public brand stylesheet + eval loop. Design intent is prose ("precise, calm, direct, technically literate, evidence-led, editorial, and restrained"). The CSS API is *published* so agents use class names rather than inventing type/spacing: "agents kept inventing their own typography, spacing, and layout, so we took those decisions away from the model entirely."
- A first attempt (porting the skill into a long prompt) failed: "every model reading it interpreted that description differently, generating vastly different pages". Fix: write from scratch against **7 frozen eval scenarios** (renewal proposal, benchmark report, planning page, deck...), "Full rounds ... on both Claude Opus 4.8 and Codex with GPT-5.5"; local app for full-page renders and **blind A/B**; every correction recorded against the run that produced it and "landed in the narrowest place that can consistently enforce it": prose in design.md, mechanics in the stylesheet, mechanical checks in code. "when a single model fails in a way the others don't, we keep it out of the rules until it repeats."
- Result: "39 of those failures" with design.md vs "91" without = 57% fewer, with explicit caveats ("six pages is far too small a sample"; checks only catch failures already written down; every page still had a ship-blocking failure).
- design.md naming effect: "Naming recurring generated-design patterns explicitly helps agents recognize and avoid them far more reliably" (blog). Its "Reject generated-design reflexes" list: tracked/all-caps eyebrows and numbered section labels; em dashes; decorative gradients/glows/blobs/stripes/textures/glass; "Generic centered hero copy followed by a card grid"; repeated metric boxes; pill badges for ordinary metadata; nested cards; "A dark rounded rectangle around every chart"; arbitrary icon tiles; tiny muted prose; "Identical section silhouettes across unrelated reader questions"; "Authoring-process narration"; stock imagery/fake screenshots. Closing counterweight: "Do not compensate for avoiding these defaults by producing a sterile anti-design template. Vercel restraint is precise hierarchy, excellent typography, clear evidence, strong alignment, and deliberate tension."
- Also: "Choose a composition specific to this material; avoid both generic model defaults and a fixed report template."; "Create presence through commitment, not additional effects... strengthen one focal relationship through proportion, hierarchy, density, pacing"; "Default to stillness."; render-fix loop: "Fix the highest-impact systemic defect, render again, and repeat."
- `product-design` skill for in-repo work: SKILL.md routes by mode (shape / implement / review / copy / harden); references split product-judgment, interface-quality, resilience, copy; rule IDs with canonical source; `exemplars/pr-*.md` of shipped decisions; `coverage-gaps.md`; linters for mechanical rules (no nested modals, 4px grid, icon-button names, no className overriding DS color/radius/shadow).

### 2.8 DESIGN.md convention (Google Stitch) and how teams give agents persistent identity

- Format: YAML frontmatter tokens (colors, typography, rounded, spacing, motion, components) + ordered markdown sections: Overview (alias Brand & Style), Colors, Typography, Layout, Elevation & Depth, Shapes, Motion & Micro-interaction, Voice & Content Strategy (added 2026-11), Components, Do's and Don'ts. Token refs `{colors.primary}`. CLI: `lint` (broken-ref error; missing-primary; contrast-ratio WCAG AA; orphaned-tokens; section-order), `diff` (regression detect), `export` (css-tailwind, json-tailwind, dtcg). Status: alpha, 29k stars, active.
- PHILOSOPHY.md is the important read: "The quality of a generated design is determined less by the precision of its values than by how clearly the intent is described." "The prose is the most vital part." "A specific reference carries more than a list of adjectives": e.g. "A graduate-level computer science lecture handout in the tradition of an old established university ... austere, informationally dense, and proudly unconcerned with first impressions." The sample tokens "serve as context and are not rendering instructions". Roles in prose carry negatives: "Vermilion is the single accent ... never on typography, never on page numerals".
- Variants of the same idea: Impeccable PRODUCT.md+DESIGN.md+surface briefs; Vercel design.md+CSS; Figma Make `guidelines/Guidelines.md` (+ granular files; "More context isn't always better. It can confuse the LLM"); interface-design `.interface-design/system.md`; Hallmark `design.md` lock ("a locked system: it overrides everything below, and pages share it") + `.hallmark/log.json`; ibelick `create-design-md`. 
- Danger: DESIGN.md of *famous brands* (VoltAgent awesome-design-md, 129k stars) tells the agent to clone a brand. For originality, the file must be **derived from our own decisions** (and from the built result), not copied.

### 2.9 Reference-driven tools

- **Refero** (read in full): methodology skill "Research is mandatory: every design must be grounded in references before implementation." Three MCP layers: Styles (semantic design references extracted from real marketing pages: visual thesis, tokens, type, composition, section rhythm, elevation, surfaces, imagery treatment, do/don't; **web marketing only**, not app screens), Screens, Flows. Workflow rules: "Do not copy one reference. Study several strong references and synthesize"; "Do not average references into a safe middle. ... choose one dominant direction and preserve its sharp traits. Secondary references may add narrow details only"; "A token's role is part of the token. Preserve it or do not use it"; "A brief is not a build target. Before implementation, lock either a user-provided visual source, an existing design-system target, a selected generated mockup, or an explicit reference-locked direction"; default three reference-locked directions, user picks; validate render vs lock. Its `anti-ai-slop.md` has 9 numbered tells + litmus tests (indigo/violet #1 tell; cards everywhere; dark by default; calm-editorial-serif on autopilot; emoji; left accent stripe; reference averaging; token role drift; fake graphics/text-only collapse) and an 18-box checklist. Paid MCP; vendor says not to use other design skills in parallel.
- **Mobbin MCP**: 620k+ screens / 153k+ flows; deep search by intent; used as "research and visual direction first" (sponsored review ranks it first; Mobbin and Refero both publish comparison pages). **21st.dev**: components as code/prompts: use *after* direction is set and adapt to your tokens. **Transitions.dev / Beautiful UI**: motion and AI-native components (secondary only). The only practitioner synthesis I found for sequencing: "evidence first, components second, motion last." (griffinwooldridge.com, sponsored by Mobbin; treat as secondary.)
- **Superdesign**: "default -> constraint" prompt shape ("name what to avoid (the AI-slop defaults) and what to aim for (a concrete reference or feeling)"), branching variants (`--mode branch`), `DESIGN.md` config. Marketing blog; adoption modest; repo quiet since June.
- **Variant, Aura**: exist (commercial design-exploration/landing-page agents; only secondary coverage found: banani, toolfolio, abduzeedo). Not verified beyond that; do not treat as sources of rules.
- **Figma Make / Lovable / Cursor / Bolt (official)**: Figma: `guidelines/Guidelines.md` is "the initial set of guidelines that Figma Make always looks at first"; keep top-level short and link granular files. Lovable (changelog 2026-05-18): "Design guidance ... For visually open-ended prompts, Lovable can generate three lightweight design directions so you can compare layouts, typography, colors, spacing, and overall visual tone before choosing one" plus Themes ("Set your brand standards once"). Cursor 2.2 (2025-12-11): visual editor in the browser (drag/drop DOM, props sidebar, point-and-describe). None of these ships an anti-slop rule set; the useful ideas are "three directions then choose" (converges with Refero, Impeccable) and "persistent guidelines file". Bolt: I did not find an official design-prompting guide (not verified).

### 2.10 Practitioner and author voices (2025-2026)

- **Paul Bakaus**, "The Dark Arts of Skill Engineering" (X article 2026-07-14; also talk video): nine techniques, the ones that matter here: make them argue (blind adversarial reviewers); force divergence ("Bans just move the model..."); route (small SKILL.md that loads one expert reference); give them memory (persist critique snapshots); scripts that talk back ("stdout is the instruction"); hooks that fight back ("The agent makes its worst edits when nobody called the skill at all"); live browser; compile per-harness; "Design for the weakest model: gates that can't be skipped". Model-specific bias: "Gemini animates images on hover; GPT crushes display type to letter-spacing: -0.06em... stacking one model's 'do not do x' rules into a skill shared with other models often regresses the others!" Also "Claude + Opus/Fable really wants to use italic serifs and eyebrow kickers (and them darn pulsating green dots)". "Slop is a moving target ... we've moved on ... into cloud beige" (talk, 2026-09).
- **Vercel design team** (above) — highest-quality practitioner evidence.
- **Tianyang Liu**, "What Is Taste in Generated UI?" (leoii22.com, 2026-09-17; long essay, academic style): useful framing, not a rule set. Notes the three recurring modes (purple SaaS shell, warm cream editorial, near-black + acid accent), that different models have different surface tendencies (Kimi K3 warmer/serif; Claude Fable 5 cool blue/cyan, sans, denser) and that "a detailed brand specification largely suppressed these differences." Conclusion consistent with everyone else: conventions are useful defaults until they become generic; specificity comes from the brief/spec.
- **Adam Wathan** (Tailwind): Aug 2025 tweet apologising that `bg-indigo-500` in Tailwind UI caused the purple-everywhere problem (as reported by dev.to, 2026-03; secondary). Root-cause story, widely repeated.
- **Charlie Hills** (design background; talk to 120 people at NatWest; Substack 2026-08-30): "I stopped describing the deck I wanted and pointed at one I already had" - brand files + Figma connection beat Gamma/Claude Design/Canva on the same brief. Illustrates: show, don't describe.
- Low-credibility/SEO pieces I read and discount: codeminerals "Taste Stack", developersdigest "16 patterns", GenDesigns, MindStudio. They repeat the consensus list but add nothing verifiable.
- Third-party comparisons: **SkillGild** (2026-10-04, one brief "Ledgerline", Opus 5, five runs): see §4 table. Self-interested (sells installs), tiny n, but transparent about method. **Itai Spector** (Medium, 2026-11): blind tests of Taste Skill, then Hallmark vs Impeccable with each skill's slop-detector grading the other's site; paywalled, only the abstract read; takeaway headline is "winner cost a third as much, and built the same website three times" (i.e. dealt/seeded diversity not validated across runs). **dani-z/frontend-design-skill-benchmark** (24 stars): "100% vs 28%" is circular (assertions are the skill's own ban-list). Treat as non-evidence.

## 5. For our anti-slop skill

Tags in brackets name the sources that support the line. "(M)" = mechanically checkable (hook/linter/DOM check), "(R)" = needs rendered page, "(J)" = judged (blind reviewer).

### 5.1 Architecture of the skill (copy the shape, not the text)

1. **Router SKILL.md under ~100 lines** that loads one reference per task (shape / build / critique / polish / audit) [I, V, Bakaus "route like a frontier model"]. Long prose gets compressed or misread by models; deliver critical forks as script output ("scripts that talk back") where possible [Bakaus].
2. **Three layers, each in its right place**: judgment as prose (DESIGN.md/PRODUCT.md), mechanics as shared CSS tokens/classes the agent reuses, anything countable as a deterministic check in code [V]. Do not put countable rules only in prose.
3. **Persistent context files** per project: PRODUCT (audience, scene, constraints, brand commitments, anti-references), DESIGN.md in Google's format (tokens + prose with *roles and negatives*, e.g. "single accent ... never on typography"), and one **surface brief per route** holding mode and a direction contract [I, G, V]. Write DESIGN.md **after** the first build from what was built, then use it as the drift baseline [I, ibelick create-design-md]. Keep it short ("More context isn't always better" [Figma]).
4. **Modes by surface**: marketing/persuade vs operate (app/admin) vs read (docs) vs experience (showcase); ambition scales with mode, apps get "precision and restraint" [I, V, H]. For our project this maps cleanly: public/invitation surfaces get full commitment; admin stays plain.
5. **Hooks/gates, not reminders**: PostToolUse hook that scans edited UI files and returns findings; a Stop-gate that blocks finishing until no FAIL remains [I, T, H]. Calibrate for weeks; provide waivers with a written reason; log waivers [I, H].
6. **Per-model tuning blocks**: a short Claude-specific block (see 5.3) kept separate from other models' rules, because "stacking one model's 'do not do x' rules ... often regresses the others" [Bakaus/I].

### 5.2 Process steps (in order)

1. **Material and brief first**: ask once for audience, the visitor's job, tone *as an extreme*, and real material (photos, copy, numbers). "Facts are never inferred" [H]. No invented metrics/testimonials/logos/customer counts/prices [H, I, T, V]; label synthetic demo data and list what to replace [I].
2. **Scene sentence**: who uses this, where, under what light, in what mood; this decides light/dark and density, not the category [I].
3. **Seven-from-the-world derivation, then deal**: list ~7 concrete visual systems/artifacts/rituals the audience knows (cultural/graphic/physical world, including "what did this look like before the web"), spanning >=3 material families; ask "what is the page this category always ships, and its predictable opposite?" and exclude both [I]. Then **pick by a random seed / dealt draw, not by taste**, and record it in a project log so the next build differs on >=3 structural axes [I, H, T]. Offer the user 3 directions (+ re-roll, + "plain category standard" as a quiet exit) [I, R, Lovable, H].
4. **Write the direction contract before any code**: thesis (and the default arrangement it refuses); own-world palette/components "recognizable with all content removed"; story; exact first viewport; the one memorable/signature element; seed ref [I, H, A]. Add a compact token plan: 4-6 named colours, type roles, layout in prose + ASCII sketch [A].
5. **Plan-vs-defaults review**: re-derive what a model would produce for a similar prompt; if the plan matches, change it and say what changed [A]. Run the **mirror test**: would a neighbouring prompt in the same category get this combination? [H] Run the **two-altitude category-reflex check** (first-order: guessable from category; second-order: guessable from category + the anti-references) [I].
6. **Refine with references, carefully**: study 3+ real sources for *patterns and quality bar*, pick one dominant direction, keep its sharp traits, forbid averaging, keep token roles intact [R]. References come from the audience's world, not only from competitors' sites [I]. Use component libraries only after direction is locked and adapt to our tokens [21st practice].
7. **Build the hero/first viewport alone**, render, review cold, then the rest [H].
8. **One memorable thing, everything else quiet**; one authored motion moment; motion answers action [A, I, H, V].
9. **Render and look** at the real widths (phone + desktop min), batched: fix everything one look shows before looking again [I, V]. Include scroll bars and a recorded motion pass if motion exists (our own lesson, not from these sources).
10. **Blind critique**: spawn two isolated reviewers: (A) design reviewer that judges specificity first ("could an unrelated product use this unchanged?"), hierarchy ("squint test"), restraint ("lost something you liked") without seeing detector output; (B) deterministic detector + browser evidence; main agent weaves them [I, H, Bakaus]. Persist a snapshot with a score and P0/P1; polish reads it [I].
11. **Waive only on the record** with a reason; the brief always wins over our taste [I, H, A].

### 5.3 Concrete, checkable rules (consensus set; tag = support)

Colour and surface
- No purple/indigo-to-blue gradient; no framework default swatch (Tailwind indigo-500/violet) as a token [I, T, H, R, U, A] (M).
- No gradient text [I, T, H, A] (M).
- No decorative glow, aurora/mesh blobs, floating blurred orbs, spotlight halos, zero-offset coloured shadows [I, H, U, V] (M).
- No glassmorphism/backdrop blur as decoration; blur only for a real layering problem [I, V, U] (M/J).
- Shadows have an offset and soft blur; do not pair a 1px border with a wide soft shadow on the same element ("ghost card"); no hard-offset shadows outside a deliberately neobrutalist world [I] (M).
- Pick colour strategy before colours (Restrained / Committed / Full / Drenched); accent area declared; not even colour distribution [I, H, R] (J/R).
- Contrast >=4.5:1 body, >=3:1 large; secondary text on a coloured ground is tinted from that ground, never grey [I, V, H, G lint] (M/R).
- Tint neutrals toward the brand hue (chroma ~0.005-0.015); avoid pure #000/#fff as large surfaces [H, T(v1), I]. (Counter-note A: do not make "tinted near-black" an unconsidered default.)
- Light vs dark is decided by the scene sentence, not by category or by "safe" [I; R differs].
- Treat "cream/ivory/paper/sand/parchment ground + high-contrast serif display + terracotta/clay accent" as a *spent default*: allowed only with a written reason tied to the product and audience [I, A, R, H]. Token names like `--paper --cream --sand --ivory --parchment` are themselves a tell [I v3.9]. **Claude-specific**: for warm, bookish, family, child-facing subjects this is the model's measured rendition prior; start from the world's saturated materials instead [I `<claude>` block].
- Near-black + one acid/neon accent is likewise a spent default [A, I].

Typography
- Choose faces from the subject's world, not from a list (including *our own* previous picks). Never accept a font because "books want a serif". Names recently on the "defaults" lists: Inter, Roboto, Open Sans, Lato, Poppins, Fraunces, Playfair Display, Cormorant, Lora, Crimson, Newsreader, Syne, Space Grotesk, Space Mono, IBM Plex, DM Sans/Serif, Outfit, Plus Jakarta, Instrument Sans, Geist/Satoshi/Cabinet Grotesk when used by reflex [I, H, A, T]. Technique: have the model name its top three, then discard all three [Bakaus]. (Weakness: any fixed denylist becomes the next list; use it as a prompt for divergence, not as a filter.)
- <=2 families (3 with a single outlier role); body >=16px at line-height ~1.5-1.65; prose measure 45-75ch (65ch target); display max ~6rem; tracking floor -0.04em (usually -0.02 to -0.03em); `text-wrap: balance` on headings, `pretty` on prose [I, H, U, V] (M).
- No eyebrow/kicker above headings, no tracked-uppercase small labels (labels = body face, one step smaller, sentence case) [A, I, H, V] (M). (Conflicts with Refero's "all caps needs letter-spacing": if caps are used for a *wordmark or deliberate system*, track them; do not use them for generic labels.)
- No one-word accent in a heading (italic, colour, highlight, underline, or a swapped face) [A, I, H, R] (M/J).
- No italic serif display system unless the brand is literally editorial [I, H] (M/J).
- No monospace for labels/meta unless content is code, data or measurement [I, H, A] (M).
- Clear hierarchy by size/weight steps; avoid flat hierarchy; headings nearer the content they head than the previous section [I, H] (R).
- Tabular numerals for data [U, I] (M).

Layout and structure
- No identical same-size icon+heading+text card grid as page structure; no nested cards; no icon-in-rounded-tile above a heading; cards only when the container is itself the interaction [I, H, A, R, V, T] (M/R).
- No hero-metric block (big number + small label + stat strip); put each number in the sentence that proves it [A, I, H, V, T-copy] (M/J).
- No "hero + three features + CTA + footer" as a default skeleton; build the page from the visitor's job and the category's real anatomy [H gate 8, V, A] (J).
- Vary spacing for rhythm; 120px+ section gaps on marketing surfaces, never one gap everywhere [I, H] (R).
- One radius per nesting level; cards <=12-16px; pill only for small controls [I, H] (M).
- No one-sided coloured stripe on cards (unless the colour encodes status and is labelled) [I, R, H] (M).
- No decorative stripes, grid overlays, textures not belonging to the subject's world [I, V, H] (M).
- Section numbers only for true sequences [A, I] (M/J).
- Container capped and centred; no horizontal scroll 320-1920; `minmax(0,1fr)` for image tracks; `dvh` not `vh` for hero [H, I, T] (M/R).
- Hero: headline + one sentence + primary action visible at 1280x800; about 80 words per screen on marketing pages (house rule; optional) [H, T].

Imagery and media
- Real or provided imagery, product screenshots, or an intentional placeholder with art direction; never CSS/SVG fakes of photographs or hand-drawn "sketch" scenes; no emoji or Unicode glyph icons; one consistent icon family and stroke [I, R, H, V] (J/M).
- Preserve the media role of a reference (image-led stays image-led) [R].
- Geometric masks do not stand in for organic cut-outs [I].

Motion
- Default to stillness; one authored moment (a page-load sequence or one reveal); no identical fade-up on every section; no hover transform on every card; no marquees, simulated typing cursors, pulsing status dots, bounce/elastic easing [A, I, H, V, U] (M/J).
- Only transform/opacity unless a specific effect needs blur/clip-path/mask; never `transition: all`; reveals must have an already-visible default; reduced-motion fallback always [I, H, U] (M).
- Motion answers a person's action [A, V].

Copy and content
- Words are design material; specific to the product; verbs+objects on buttons (`Save changes`, never `Submit`); sentence case; the same action keeps one name across the flow; errors name the problem and recovery, never apologise [A, I, V].
- No stock phrases/ban-words (elevate, seamless, unleash, delve, tapestry, leverage...), no em-dash habit, no "X. Y." fragment headings, no question-then-answer reveals, no `A · B · C` meta strings, no `→` appended to links, no invented specifics (fake times, batch numbers, percentages) [T copy-tells, I, A, H] (M via copy lint).
- Avoid "house voice" (warm, wry, modest, literary for every client); pick a register per client [T].
- No authoring-process narration on the page ("why I organised it this way") [V].

States and craft floor
- Hover, focus-visible, disabled, loading (structural skeletons), error, empty (one clear next action), real content, keyboard focus, reduced motion [I, U, H, T-v1] (M/R).
- Theme the browser surfaces we did not draw: text selection, caret, scrollbars, focus ring, underline offset, tabular numerals [I] — the cheapest "this was built, not assembled" signal.
- Destructive actions confirm with named object+consequence (`AlertDialog`) [U, V].

### 5.4 Evaluation methods to adopt

1. **Deterministic layer**: adopt/clone the *idea* of Impeccable's detector (source + rendered), implement the rules above as lint/DOM checks; run via PostToolUse hook and at finish; report P0-P3; waivers require a reason [I, H, V].
2. **Fixed scenario set** of ~5-7 representative surfaces for us (e.g. couple landing, guest RSVP page, invitation card, admin list, email), frozen inputs and viewport; generate with and without the skill; **blind A/B** review; record each correction against the exact run; land it in prose, shared CSS, or a check; re-run affected scenarios [V].
3. **Mirror/variety test across runs**: log structural axes of each build (hero posture, nav, palette family, type pairing, section silhouette); require difference from the last 3 [H, I, T].
4. **Two-agent critique** (design reviewer blind to detector; detector separate), then weave [I]. Score with a short rubric: Philosophy / Hierarchy (squint test) / Execution / Specificity ("could belong to no other product") / Restraint / Variety [H] plus "design specificity: could an unrelated product use this unchanged?" [I].
5. **Screenshot at phone + desktop (+ real scrollbars/motion pass)** for every verification [I, A, V].
6. **Track the denylist's own decay**: keep tells in a dated file; re-review each model generation ("the tells move with every model generation") [T copy-tells, Bakaus].

### 5.5 Weaknesses and traps to design around

- **Ban-list substitution**: "tell it not to use Inter ... it just uses the next best font" [Bakaus]. Evidence: Anthropic's 2025 recommended fonts became 2026 tells; taste-skill v1 recommended Geist/Satoshi/Cormorant; purple -> beige serif. Mitigation: seed from outside the model, make the model discard its top three, pair every ban with a positive move [T], and keep the ban list as *detection*, not as the only generation instruction.
- **Over-compensation into sterile anti-design** [V: "Do not compensate ... by producing a sterile anti-design template"]; the "no eyebrows, no labels, no gradients, no animation, no cards" combination can yield a bland minimal page (ibelick baseline-ui is exactly that by design). Add a **positive requirement**: one memorable, product-specific thing per surface [A, H].
- **Template kits converge across users** (taste-skill v2.5's fixed starter + 11 heroes; UI UX Pro Max's category->style table; Hallmark's 50 themes). A finite catalog is better than free convergence but is still finite. For us, a catalog of >=9 worlds is fine only if the *seed log* prevents repeats within the project and our worlds are authored from our subject, not borrowed brands.
- **Reference averaging** and **token-role drift** [R]; **copying a famous brand's DESIGN.md** [VoltAgent collections] gives pastiche, not originality.
- **First-order category reflex** (UI UX Pro Max: spa -> soft pink + Cormorant); also second-order (avoiding SaaS-cream lands in "editorial typographic") [I].
- **Brief-vs-taste conflicts**: pinned user brief must beat the skill; the skill must not "redirect a clear brief toward your taste" [I, A]. (For us: the owner's chosen logo/palette/designs are pins.)
- **Self-grading bias**; the detector anchors the reviewer; thus blind two-agent critique [I].
- **Cost and length**: Impeccable's full new-work path = 7.6x tokens; Anthropic's skill = 1.6x for most of the benefit. Keep the always-on layer small; put heavy procedures behind explicit invocation; use targeted checks (matches our "targeted checks" practice).
- **Hook risk**: hooks run outside model approval and can burn tokens/overcorrect; need calibration and ignore mechanisms [Impeccable README, Bakaus].
- **Browser launching**: Impeccable `detect <url>`/`shot`, taste-skill scripts and Hallmark `sloplint --render` launch a system Chrome/Edge; on this Mac the rule is chrome-headless-shell only (set `CHROME_PATH` / patch launcher to `~/.cache/puppeteer` chrome-headless-shell, always close in `finally`). Verify before running any of them.
- **Telemetry/catalog fetches** (Impeccable) and third-party catalogs: review before adopting; prefer vendoring ideas over installing.
- **Evidence is weak**: treat claims of "100%" or star counts as marketing; build our own scenario evals.

### 5.6 What to adopt vs skip (opinionated)

Adopt: Impeccable's modes, direction-contract-before-code, seven-from-the-audience's-world derivation, seed/deal + history log, two-altitude reflex check, blind two-agent critique, PostToolUse detector idea, "browser surfaces" floor; Hallmark's tiered Floor/Reflex/Finish, mirror test, hero-first build, six-axis pre-emit critique, "material first/facts never inferred"; Anthropic's plan-then-review-vs-default, "spend boldness in one place", calibration list (including noting our own accent colours as tells); Vercel's three-layer placement + blind A/B eval harness + "name the patterns"; Google DESIGN.md format and `lint`; taste-skill's copy-tells with positive moves; Refero's no-averaging and token-role rules; ibelick's three-proof gate for audits and MUST/NEVER phrasing for mechanical rules.
Skip: UI UX Pro Max-style category lookup tables; awesome-design-md brand clones; taste-skill v2.5 template kit and mandatory motion; any benchmark whose rubric is the ban list; long-tail "anti-slop" repos.
Unverified / not covered: Bolt's official design guidance, Variant and Aura beyond secondary mentions, Mobbin MCP docs (vendor blog/secondary only), Emil Kowalski and Vercel web-interface-guidelines rule contents (not read), Medium articles behind paywalls.
