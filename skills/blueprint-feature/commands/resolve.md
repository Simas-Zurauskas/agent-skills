# resolve — apply answers before reviewing the result

Read [rules](../reference/rules.md), [feature shape](../reference/feature-shape.md), and
[record](../reference/record.md).

1. Record invocation answers/overrules and owner edits first. Queue Answered rows in dependency order.
   Empty answers remain unapplied; ambiguous answers are Flagged with a reason; open dependencies wait.
2. Draft only what each answer entails. Owner supersession quotes replaced text. A delegated ordinary
   answer fills its gap without overriding owner material or unrelated accepted promises. If it needs
   an unresolved serious choice or such a rewrite, Flag it; do not invent the missing authority.
3. Apply the queue as one coherent update, checking concurrent edits before each file replacement.
   Keep provenance, stable IDs/tombstones, explicit remaining gaps and re-opened dependents. Applied rows
   get Applied date; Flagged rows get Why flagged. Remove only settled markers and regenerate Open
   questions. A no-op answer can be Applied with evidence of the existing carrying line.
4. No mandatory per-eight-answer checker. The combined or builder/adversary review checks that the
   resulting definition faithfully entails answers, preserves limits, and agrees across dependencies.
   Use [grill](../reference/grill.md) for affected scope, correction bounds and reuse. A chained add/auto/
   ready reviews once after all known material is applied. Serious blockers can defer final review.
5. Lint, sync, snapshot and close one shared entry. Report actual applied/superseded lines, Flagged or
   unresolved decisions and review residuals. A ready stamp is only the ready command's responsibility.
