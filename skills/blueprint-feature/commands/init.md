# init — define one existing-product change

Read [rules](../reference/rules.md), then:

1. Resolve/scaffold the home, probe write, check lock and lint, open one run, save invocation/sources
   and supplied decisions ([record](../reference/record.md)). A home with existing requirements uses add;
   a matching paused init resumes. Read real project guides and authority before interpreting intent.
2. If actor/outcome are still unknowable after available task context, ask one short bundle (at most
   three questions), preserve the draft/source state, pause. Do not invent a feature.
3. Map relevant code/docs directly and write [baseline](../reference/baseline.md). Broad discovery may
   use non-overlapping cartographers; there is no required mapper/verifier pair. Record checkout/dirty
   state and actual known/unknown release evidence.
4. Draft every applicable [feature block](../reference/feature-shape.md), using supplied intent, current
   facts, eligible labelled defaults and bounded slots. Include failable FR, affected CH/KEEP and relevant
   edge/lifecycle/compatibility. Do not intentionally leave ordinary gaps for later agents to fill.
   Apply rules §4's scope test before every new promise. Record serious unknowns as rows/markers through
   [finding handling](../reference/dispositions.md); do not generate a question per empty section.
5. `soft`: snapshot and pause for the owner's look, clearly unreviewed. Otherwise review at the useful
   boundary under [grill](../reference/grill.md). If serious decisions block a settled draft, ask them
   early and defer exhaustive review. If this invocation also requests ready/auto, that caller performs
   the single final review instead of paying for duplicate review here.
6. Apply evidence-backed corrections as one batch and obtain necessary targeted rechecks within the
   bound. Missing coverage stays explicit. Sync IDs, regenerate Open questions and close per record §6.

Standalone init leaves Draft even after clean review; `ready` alone stamps planning readiness. A chained
ready may reuse the exact clean coverage. Do not prompt for an extra approval of ordinary defaults.
