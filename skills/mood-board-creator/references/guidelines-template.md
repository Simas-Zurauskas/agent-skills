# Product guidelines (normal and thorough)

This template is a prompt, not a line-count quota. Read [design-diagnostics.md](design-diagnostics.md).

```markdown
# <Product> exploration guidelines

## Product and owner constraints
Audience, task, locale, sources, explicit never-rules and owner decisions. Mark assumptions. State precedence:
owner/product constraints > fixed content and approved brief > critic preferences.

## Product truths and intended quality
A few sourced truths that can become visual ideas. Relevant reference screenshots and what level/behavior they
illustrate. Distinguish the desired quality from a requirement to copy their style.

## Useful design space
Which axes matter to this round: composition, type, information emphasis, density, imagery, color, material, motion
only if scoped. Note constrained/shared axes honestly. Do not relax owner rules to fill a matrix.

## Relevant craft checks
Exact content, ordinary usable controls, fit, real fonts/images, readable hierarchy, useful consistency and target
requirements. Select relevant checks from craft-floors.md; no blanket hero, surface-count or font requirements.

## Evidence and review
Target links/capture tools, actual screen dimensions, screenshot inspection, local evidence paths, substantive
finding format. No compulsory aesthetic scores. Same configured builder effort in every mode.

## Technical contract
Link the selected target guide. State disjoint variant ownership and the single publisher; do not duplicate target
implementation instructions. Shared image library, allowed local scope and server owner.
```

Normal/thorough prep reviewer checks product fidelity, unclear instructions, actual feasibility and overconstraint.
Report only concrete findings. Revising records accepted changes and reasons for rejected preferences. Product
constraints are never rewritten by a critic. Historical reference bans apply only if the owner or product actually
requires them.
